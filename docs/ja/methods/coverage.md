# カバレッジ

[English](../../methods/coverage.md) | 日本語

**executed** 列（[基本概念](../concepts.md) を参照）を埋める手法です。そもそもどれかのテストがこのメソッドを実行したかを調べます。

## 何をするか

カバレッジは自前で計測しません。`swift test --enable-code-coverage` が出力する `llvm-cov export` の JSON を読み、その中の関数を、メソッド本体の開き括弧 `{` の位置で発見済みのメソッドに対応付けます。

結果は 2 つの用途に使います。

1. どのテストも実行しないメソッドを `not-covered`（PIE の E が不成立）として報告する。これは `pseudo-tested` とは別の問題で、対処も違う（アサーションを足すのではなく、テストを書く）。
2. 実行されないメソッドを、verified 列を埋めるより高コストな手法の対象から外す。一度も実行されないコードの故障は検出しようがないので、調べても時間がかかるだけである。

## 出力

解析したメソッドごとに、JSON レポートの `executed` にこの列を出します。値は `"true"`、`"false"`、`"unknown"` のいずれかです。値はカバレッジから埋めますが、殺されたミュータントがあれば `"true"` で上書きします。テストがメソッドの振る舞いの変化に気づいたのだから、メソッドは実行されています（動的な証拠が優先。[基本概念](../concepts.md) を参照）。タイムアウトしたミュータントは数えません。マシンが遅いだけでもタイムアウトは起きるからです。

その結果、`unknown` のまま残るのは、すべてのミュータントが生き残ったメソッドだけです。テキストと Markdown のレポートでは、こうしたメソッドに注記を付けます。生き残ったミュータントだけでは、検証されていないのか、そもそも実行されていないのかが分からないからです。実行全体でカバレッジが使えなかった場合は、注記の代わりにヘッダーで一度だけそう示します。

## カバレッジが使えないとき

| 状況 | 振る舞い |
|---|---|
| `--no-coverage` | カバレッジを取得しない |
| カスタムモードで `--coverage-profdata` と `--coverage-binary` がない | カバレッジを取得しない |
| カスタムモードで、ベースラインが `.profdata` を書き出さなかった（`-enableCodeCoverage YES` がない）、またはカバレッジデータを持つバイナリがない | メッセージを出し、カバレッジなしとして扱う |
| カバレッジデータを読めない・解析できない | メッセージを出し、カバレッジなしとして扱う |
| データ中に対応する関数がないメソッド | そのメソッドを不明として扱う（ただし [条件付きコンパイル](#条件付きコンパイル) を参照） |

いずれの場合も executed 列は不明になり、verified 列の手法は該当する全メソッドに対して実行されます。その結果、どのテストも実行しないメソッドは `not-covered` として報告されず、検証で不合格になります（たとえば極端ミューテーションでは `pseudo-tested`）。カバレッジが使えたかどうかはレポートに表示されます。

## 条件付きコンパイル

どの `#if` 節が有効かはビルド（`-D` フラグ、ターゲットプラットフォーム、利用できるモジュール）にしか分からないので、ツールは有効・無効にかかわらず `#if` のすべての節を解析します。これをカバレッジデータで判定します。llvm-cov は、どのテストも実行しなかった関数も含めて、コンパイルされた関数をすべて列挙します。そのため、`#if` の中で宣言され、データ中に関数がないメソッドはコンパイルされていないと判断し、ミューテーションせずに *Not analyzed* として報告します。

カバレッジがないとこの判定はできず、無効な `#if` 節の中のメソッドは `pseudo-tested` として報告されます（ミュータントがバイナリに存在しないので検出されようがない）。

## 限界

- カバレッジは *偶発的な* 実行も実行済みとして数える。統合寄りのテストの深い呼び出し経由で実行されるだけのメソッドは、責任を持つテストがなくても `executed` になる。`referenced` 列はこれを見えるようにするためのもの（[基本概念](../concepts.md#テストが欠けているの-4-つの意味) を参照）。
- 条件付きコンパイル、プラットフォーム分岐、非同期の実行タイミングによって、実行ごとにカバレッジがぶれることがある。
